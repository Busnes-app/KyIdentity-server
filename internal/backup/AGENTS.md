# Backup

## Purpose
KyIdentity's adapter over `github.com/Busnes-app/ky-primitives/recoveryclient`, the suite's product-side backup package. The lib decides everything about keys, pairing, destinations, schedule, sealing, drilling and restoring; this package says what KyIdentity seals, what its drill checks, and how the store, the deployment key and the config map onto the lib's interfaces.

## Ownership
- `payload.go`: `CollectSealable` (database snapshot through the live handle, a SQLite file on either backend (`store.SnapshotTo`), RSA signing key, encryption and secret keys, `recovery.pub`, the VAPID key (at `config.VAPIDKeyPath`) and any leftover `push-relay-*.key` files; self-registered relay keys now travel inside the database, table `push_relay_keys`, plus `PUSH_RELAY_KEY`/`APNS_RELAY_KEY` under the file name `mfa.RelayKeyFile` gives them, config manifest), `Members`, the capsule paths, the verification recipe. A snapshot over `capsule.MaxFileBytes` is sealed as ordered `data/kyidentity.db.partNNN` members (owner decision: large databases in backups); a snapshot that fits stays the single `data/kyidentity.db`. `JoinDatabaseParts` rebuilds the file and is called by `restore` and by the drill before any check; `required_files` names the joined file. Collection logs a warning once the payload reaches 80% of `capsule.MaxExpandedBytes`, the limit a gzipped capsule reaches first. Never raise the library limits. `TestLargeDatabaseIsSplitAndJoinedBack` covers it.
- `scratch.go`: `lockedScratch` makes the 0700 `snapshot-*` directory `CollectSealable` writes the plaintext database into and holds an exclusive `flock` on it until it is removed; `SweepScratch` (server start) removes only unlocked `snapshot-*` directories this user owns, never following a symlink, re-checking that the path still names the locked inode (`TestSnapshotScratchIsPrivateLockedAndSwept`).
- `drill.go`: `RunRestoreDrill` runs `recoveryclient.Drill` with `DataDir` as the scratch root and adds KyIdentity's checks from the authenticated, reopened manifest recipe: required files, SQLite integrity and application records, MFA secrets, paired-system tokens, mail settings, HR writeback tokens and stored push relay keys open for their row (legacy ciphertext only when the restored database lacks `store.SealedSecretsSetting`, mirroring startup), the signing key issues a verifiable token. A "Recovery Key" check reports pin status; the drill never touches the suite key.
- `adapter.go`: type and error aliases under the names the handlers use; `settings` maps `*store.Store` onto `recoveryclient.Settings` (`store.ErrNotFound` → `recoveryclient.ErrNotFound`); `Coherent` serves one operation's pairing and pin rows (`pairingKeys`: URL, sealed token, key ID, threshold, total shares, sealed public key) from one `Store.GetSettings` statement on first read, passing writes and other keys through, and every public reader (`RunBackup`, `LoadPairing`, `LoadRecoveryKey`, `StoreRecoveryKey`, `KeyPinned`, `HasPairing`, the Status handler) wraps its store in it (`TestPairingReadsAreCoherentUnderConcurrentRepairing`, both drivers); inside `EditSettings` it reads key by key, already serialised; `sealer` wraps `crypto.EncryptAESGCM(crypto.DeriveKey(EncryptionKey, "kysignon:setting:kyrecovery_token"))` so pairings sealed before the lib keep opening (`TestAPairingSealedBeforeTheLibStillOpens`); `RunBackup` builds `RunConfig` from `config.Config` and passes `CollectSealable` as the collect func.

## Local Contracts
- One backup and one drill at a time across replicas: every caller of `RunBackup` (scheduler, Back up now, `deposit`) holds the `Lease` database lease, and every drill holds `DrillLease`, through `store.HoldLease` with `LeaseTTL` (2 min, renewed every 30 s on the database clock). The run's context is the lease's: a lost lease, or the shutdown's cancel phase, ends the upload, and the outcome is still audited through `Outcome`. The library's own lock is per process. `ApplyRestoredState` deletes leases, because every capsule is taken while its server holds `Lease`.
- A settings read that fails is an error, never "unpaired" or "not pinned": `KeyPinned` and `HasPairing` return `(bool, error)`, Status answers 503, Back up now and export answer 5xx, and the scheduler audits a failed `admin.backup_run` (`TestUnreadableSettingsAreNotUnpaired`, `TestBackupReadErrorsAreNotUnpaired`, `TestUnreadableSettingsAreAFailedScheduledRun`).
- A pinned key's k-of-n is written once: `StoreRecoveryKey` refuses the pinned key with another topology (`ErrTopologyChanged`, wraps `fs.ErrExist`, 409) inside the same `EditSettings` transaction, before anything is written; the same topology stays idempotent (`TestPinnedTopologyIsWriteOnce`, `TestPinnedTopologyIsWriteOnceOverHTTP`, `TestConcurrentPinsOnTwoServersHaveOneWinner`).
- Do not reimplement anything the lib provides. If a behaviour is missing, add it to `recoveryclient` and bump the dependency.
- The sealer label is fixed forever; changing it orphans every live pairing.
- `KYIDENTITY_BACKUP_DIR` is per replica by default or one directory every replica shares (the operator provides the shared filesystem). Writing, pruning to `KEEP` and migrating the exact legacy `KySignOn-cap-KySignOn-<unix-nanos>.kycap` shape to the library prefix happen only in `RunBackup`, under `Lease`; `ListLocalCopies` (the Status page) only reads. Unrelated files are never renamed or pruned (`TestLegacyLocalCopyIsMigratedWithoutTouchingForeignFiles`, `TestLocalBackupDirectoryLayouts`, `TestBackupStatusNeverChangesTheBackupDirectory`).
- Settings keys are the lib's (`kyrecovery_*`, `backup_*`); the store just holds rows.
- `TestNothingInTheServerDecrypts` runs `guardtest.NoDecryptOutside` on the repository with `cmd/kyidentity/main.go` `restore` as the only allowed caller. It was proven by planting `capsule.Open` in a handler and watching it fail.
